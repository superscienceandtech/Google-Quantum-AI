## 3. Architecture and public API

`KaggleAcquisitionAdapter(repository_root, limits=None)` confines downloads to
`external/acquisition-staging/invsqrt/`. Each approved download is directed
to a newly created UUID subdirectory; existing files are not used as a
download destination.

Public types and operations:

| API | Responsibility |
|---|---|
| `PreflightStatus`, `PreflightResult` | Machine-readable readiness result, detected CLI path/version, non-secret auth hints, blockers, and diagnostic code |
| `AcquisitionLimits` | Bounded CLI timeouts, file size, archive member count, and expanded archive size |
| `KaggleAcquisitionAdapter.preflight(...)` | Verify exact slug, staging path, discovered CLI/version, and authentication result |
| `KaggleAcquisitionAdapter.build_download_command(...)` | Construct an immutable argument tuple for the discovered Kaggle executable |
| `KaggleAcquisitionAdapter.download(...)` | Run one explicit CLI download only after successful preflight |
| `DownloadStatus`, `DownloadResult` | Distinguish blocked, successful, failed, and timed-out transfers without retaining raw CLI output |
| `inventory(...)` | Enumerate regular staged files, record size/readability/SHA-256/retrieval/source/status, and inspect archives without extraction |
| `ArchiveStatus`, `ArchiveInventory`, `ArchiveMember` | Describe safe, unsafe, oversized, unreadable, or non-archive files and their checked members |
| `extract_archive_members(...)` | Explicitly extract only caller-selected regular members from a safe archive into a new staging subdirectory |
| `map_artifact_roles(...)` | Resolve explicit exact-path evidence mappings; report missing and ambiguous roles without filename guessing |
| `handoff_to_p005(...)` | Create P005 schema-v2 declarations from explicitly mapped staged files |
| `assess_p005_readiness(...)` | Reuse the existing P005 fail-closed readiness assessment |

The role map recognizes INVSQRT verifier, reference circuit, sample
submission, official scoring implementation, competition metadata, runtime
specification, and SDK library roles. The code defines role names and stable
IDs, but does not guess archive member names or auto-map by filename.

## 4. Acquisition state machine

1. **Identity gate:** accept only the exact P014-verified slug. No caller
   override is silently used.
2. **Destination gate:** accept only the approved repository-local staging
   root or a descendant. Reject parent traversal, protected repository
   locations, symlinks, junctions, non-directory output paths, and paths
   outside the approved tree.
3. **CLI gate:** find `kaggle` using `shutil.which`, require a regular file,
   execute only its `--version` command with a short timeout, and retain only
   a narrowly parsed version token.
4. **Authentication gate:** inspect only recognized environment-variable
   *names* and the standard config file's presence; never read values or file
   contents. Such presence yields only an unverified hint. Unless the caller
   provides a separately vetted read-only `authentication_probe` that returns
   true, preflight returns `AUTHENTICATION_UNAVAILABLE` or
   `AUTHENTICATION_UNVERIFIED`.
5. **Download gate:** only `READY` preflight allows one
   `kaggle competitions download -c <verified-slug> -p <fresh-run-dir>`
   invocation. There is no shell interpolation and no automatic retry.
6. **Inventory gate:** require a successful download result. Inspect regular
   files and archives without importing or executing contents. Unsafe or
   unexpected objects fail closed.
7. **Explicit mapping/extraction:** member selection and extraction are
   caller-initiated. No archive is automatically extracted. Exact paths must
   be observed, safe, unique, and unambiguous.
8. **P005 handoff:** use P005's schema-v2 `ArtifactDeclaration` and
   `ArtifactManifest.discover`. Transfers remain
   `OFFICIAL_SOURCE_UNVERIFIED`; downloaded bytes supply a calculated hash,
   not an independently expected hash or official-authentication evidence.
9. **Readiness gate:** P005's existing integrity/provenance checks remain in
   force. Missing role mappings, absent files, no expected hash, or
   unauthenticated provenance continue to block readiness.

## 6. Preflight and authentication behavior

- CLI discovery uses `shutil.which("kaggle")`; version acquisition runs
  `<discovered-executable> --version` as an argument array with a five-second
  default timeout.
- Environment checks compare names only (`KAGGLE_USERNAME`, `KAGGLE_KEY`,
  `KAGGLE_API_TOKEN`) and check whether `~/.kaggle/kaggle.json` is a file.
  Values and file contents are never accessed or included in results.
- Config presence is reported as an unverified hint, not as successful
  authentication.
- No authenticated request is made by default. A caller-supplied probe must be
  independently reviewed for the installed CLI version and be non-mutating;
  its only accepted output is a boolean.
- Default preflight with no available CLI/authentication returns a blocked
  result; the default download method will not create the staging directory
  or invoke the competition download command in that state.

## 7. Secure subprocess behavior and error handling

- Subprocess invocations use tuples/lists of arguments and `shell=False`.
- The download uses a configurable bounded timeout (600 seconds by default);
  CLI version uses a separate five-second timeout.
- Download results distinguish `BLOCKED`, `SUCCEEDED`, `TIMED_OUT`, and
  `FAILED`, with exit code and generic diagnostic code.
- Stdout/stderr are captured in memory only to determine whether output
  existed. Raw output is not retained in result objects, exceptions, or logs,
  which avoids leaking credentials or arbitrary CLI diagnostics.
- No automatic retry occurs. Timeout and process-launch failures do not expose
  exception output or credential values.
- A new UUID staging directory is created only after preflight is ready.
  Existing staging files are preserved and never selected as the destination.
- The command builder rechecks that its executable matches the currently
  discovered Kaggle CLI.

## 8. Staging and archive safety

Inventory rejects symbolic links, junctions, and unexpected filesystem
objects; opens regular files with no-follow semantics where supported and
checks the opened file identity; bounds individual files at 1 GiB by default.
Staging paths are constrained under the repository's dedicated acquisition
area, with source, test, `.git`, results, and historical evidence locations
excluded by construction.

ZIP and TAR inspection does not extract members. It validates member paths
against absolute paths, drive/UNC paths, traversal, alternate-data-stream
colons, duplicate normalized paths, symlink/special-file types, member count,
per-member size, and aggregate uncompressed size. Defaults are 100,000
members and 2 GiB total expanded size. Corrupt archives with archive-like
extensions are reported as unreadable rather than treated as valid files.

`extract_archive_members` is a separate explicit operation. It accepts only
selected regular members from a safe archive, requires a new destination
inside staging, creates outputs exclusively without replacement, checks
declared versus actual size, and never executes extracted files. Partial
output after an extraction error is left in the run directory for inspection;
no broad cleanup or retry is performed.

## 9. Inventory and explicit artifact-role mapping

For each staged regular file, inventory records relative path, original
filename, size, SHA-256, readability, file type/archive state, archive member
paths where safely inspectable, source slug, UTC retrieval time, download
result, and `OFFICIAL_SOURCE_UNVERIFIED` provenance.

The role-mapping API requires exact paths supplied from observed archive or
filesystem evidence. It reports `MISSING`, `MAPPED`, or `AMBIGUOUS`; it does
not decide that a matching filename is canonical. A single observed file
cannot fill multiple roles. Duplicate candidates and multiple matches remain
ambiguous and are not passed to P005.

The API identifies these requested roles when the caller provides mappings:
INVSQRT verifier, reference circuit, sample submission, official scoring
implementation, competition metadata, runtime specification, and Kickmix
library. No role is marked available merely because it was named in this
list.

## 10. P005 provenance integration and P003 preservation

For each explicitly mapped file, `handoff_to_p005` creates a schema-v2
`ArtifactDeclaration` using:

- the P014 competition slug as `source_identity`;
- the official competition page as `source_url`;
- a P015 retrieval/source note in `provenance`;
- the actual SHA-256 calculated by P005 discovery;
- no `expected_sha256` unless an independently obtained trusted digest is
  added later;
- no fabricated authentication evidence; and
- `ProvenanceStatus.OFFICIAL_SOURCE_UNVERIFIED`.

P005 therefore reports file bytes and a calculated digest while keeping
integrity verification and official authenticity distinct. A successful
Kaggle CLI exit and a source-linked transfer do not by themselves establish
which archive member is the canonical verifier/circuit/sample. `assess_adapter_readiness`
continues to require authenticated provenance and an independently matching
expected SHA-256 for each required role. The official scoring implementation
is inventoried/mappable but does not replace P005's required verifier,
reference, and sample roles.

default and retains its explicit authorization and official-execution gates.

## 14. Security limitations and remaining blockers

- P015 does not prove that the configured Kaggle account has competition
  access unless an approved authentication probe reports success.
- A successful download from the verified competition slug is source-linked
  transfer evidence, not proof that each role mapping is canonical.
- No independent expected hashes or canonical archive-member map are
  currently available; P005 must remain blocked.
- File-system checks are fail-closed and use no-follow/open-identity checks
  for regular-file reads, but no user-space path validation can fully prevent
  a hostile same-user process from racing mutable directories on platforms
  without directory-handle-relative operations.
- Archive limits bound members and declared expansion sizes; they do not
  certify archive contents as trustworthy.
- No downloaded Python, verifier, circuit, or binary is executed or imported.
- Kickmix and the official verifier remain unavailable in this environment.
